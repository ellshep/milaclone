# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm start                     # run the app (default http://localhost:4321)
docker compose up -d --build  # run in Docker on 127.0.0.1:8182
PORT=8080 node server.js      # run on a different port
npm test                      # backend + API tests (node --test), fails under 80% line/branch/function coverage
node --test test/api.test.js  # run a single test file
npm run test:ui               # Vitest + jsdom unit tests for front-end modules (test/ui/*.test.mjs)
npm run test:e2e              # Playwright end-to-end tests
npx playwright test e2e/ui.spec.js -g "creates a note"  # single e2e test
npx playwright install        # one-time: fetch browser binaries for Playwright
npm run lint                  # oxlint; warnings fail CI
npm run format                # prettier --write (CI runs format:check)
```

CI (`.github/workflows/tests.yml`) runs Lint, Format, Unit / API tests, UI unit tests, E2E tests and Docker smoke on every PR; all six are required checks on `main`, so job names must not change without updating branch protection. The E2E job runs in the `mcr.microsoft.com/playwright:v<version>-noble` image — bump that tag with `@playwright/test`. Coverage floors: `npm test` applies 80% to all backend files; Vitest applies 80% per file to the modules listed in `vitest.config.mjs` thresholds — add a module there when it gets unit tests. Modules that import `main.js` boot the whole app, so test them in Playwright instead.

The backend and e2e suites are self-isolating: `test/api.test.js` points `DATA_DIR` at a fresh `mkdtemp` before requiring `db.js`; `playwright.config.js` starts its own server on port 4322 with `DATA_DIR=.e2e-data` (wiped each run). Neither touches real board data — but note that `db.js` opens the SQLite handle on `require`, so any code that requires it must set `DATA_DIR` first if isolation matters.

## Architecture

Three-file Node backend + vanilla ES-module frontend. The only build step is the rich-text editor: `server.js` runs esbuild `buildSync` at boot, bundling `public/js/editor.js` (TipTap) into the gitignored `public/vendor/editor.js`; nothing else is bundled. `esbuild` and the `@tiptap/*` packages are runtime `dependencies` (exact-pinned) because the Docker image builds the bundle on start.

**Backend flow** (`server.js` → `routes.js` → `db.js`, plus `export-md.js`):

- `db.js` opens `better-sqlite3` in WAL mode on import, creates schema on first run, and seeds a root `Home` canvas. It exports prepared statements (`stmt.*`) and helpers; **routes call the prepared statements directly** rather than going through a repository layer.
- Schema: `canvases` (self-referential tree via `parentCanvasId`), `items` (belong to a `canvasId`, may nest under `parentItemId` for cards inside a column), `meta` (key/value; stores `rootCanvasId`).
- `items.data` is a JSON string in SQLite but always an object at the API boundary — `rowToItem` parses on read, routes `JSON.stringify` on write.
- **Rich text:** `note` and `comment` items keep one body — `data.doc` (TipTap JSON) plus `data.text` (its plain text; anything that searches or labels a note reads `text`). `db.js` `toRich` converts plain-text writes (`title`/`body`, e.g. from the importer or a paste) on POST, and `migrateRichText` converts old rows once at boot after a `VACUUM INTO` backup (`board.pre-richtext-*.db` in `DATA_DIR`).

**The board/canvas duality is the trickiest invariant.** A `board`-type item on canvas A owns a freshly-created child canvas B (see `routes.js` POST `/api/item`). The card's title, color, and icon live on the child canvas row, not the item — GET `/api/canvas/:id` augments board items with `_childTitle`/`_childCount`/`_childColor`/`_childIcon`, and PATCH writes title/color/icon _through_ to the child canvas and strips them off `item.data`. Deleting never removes rows: `trashItemDeep` in `db.js` tags the item and its whole subtree (column cards, nested canvases and their items) with `trashedBy = <item id>`, and every prepared statement filters `trashedBy IS NULL`, so trashed rows look deleted. `POST /api/item/:id/restore` clears that tag (toast Undo / cmd+Z, or the Trash sheet); it returns 409 when the item's board is itself trashed, and a restored card whose column is gone comes back loose. `GET /api/trash` lists one entry per delete (rows where `trashedBy = id`), and `DELETE /api/trash` hard-deletes every trashed row and unlinks upload files no surviving item references (`json_extract(data, '$.src')`). A `parentItemId` sent to either PATCH route must name a live `column` on the item's own canvas, or the request is rejected with 400. `GET /api/search?q=` matches board titles and card text (`data.text`, titles, URLs, file names, to-do tasks) on live rows only, with LIKE wildcards escaped. `GET /api/canvas/:id/export.md` (`export-md.js`) writes a board in the Markdown shape `scripts/import-milanote-md.js` reads back — keep the two in step (the round-trip is tested in `test/findkeep.api.test.js`); nested boards are flattened to `#` sections because the importer nests one level. `GET /api/backup` streams a `db.backup()` snapshot. Copy and cut/paste are server-side too (`/copy` deep-copies via `collectSubtree`, `/move` re-parents and refuses moving a board inside itself).

**Frontend** (`public/js/*.js`, ES modules loaded via `<script type="module">` from `index.html`):

- **Selection** is a set: `state.selection` holds every selected id and `state.selectedId` is the primary one (rename, board chrome). Go through `select` / `selectIds` / `toggleSelect` in `editing.js`, never assign either field directly; `selectedItems()` drops cards whose column is also selected. Left-drag on empty canvas draws the selection box (`tools.js`); space-drag, middle-drag and touch pan (decision D2). Copy/cut/duplicate/delete/colour act on the whole selection — the clipboard and its marker carry an id list, and paste keeps the cards' relative layout. Dragging raises cards (`z`); Bring to Front / Send to Back renumber `z` (it may go negative).
- **Keyboard:** the global `keydown` in `main.js` owns every canvas shortcut; the `/` sheet (`#shortcutsDialog` in `index.html`) is the user-facing list, so update it with any new key. Zoom keys run before the typing guard so the browser never zooms the page. Drags snap the lead card to `GRID` (`util.js` `snap`, shift = free) and arrows nudge via `drag.js` `nudgeSelection`.
- `state.js` is the shared mutable app state. Because ES module bindings can't be reassigned by importers, anything that mutates at runtime (`view`, `cam`, `selectedId`, `drag`, …) lives as a field on the exported `state` object; collections mutated in place (`elMap`) are exported directly.
- `main.js` is the entry point: boots, wires global keyboard/pointer handlers, and owns `openCanvas(id)` — the single navigation primitive that fetches, resets selection, and updates `location.hash`.
- `cards.js` owns all DOM rendering for items. `render()` clears `#world` and re-renders everything; `refreshItem(it)` swaps a single card. Cards inside a column render as children of the column's DOM, not directly under `#world`.
- `drag.js` handles drag-in/drag-out of columns: dragging a card out of a column reparents it to `#world` mid-drag and clears `in-column`; dropping onto a `.col-body` reparents and reorders siblings via `api.patchMany`.
- `quicknotes.js` owns the mobile-only **Quick notes** workspace (`#quicknotes`, shown by the footer's "Quick notes" tab): a three-level stack (overview → list detail → task detail) plus a modal search layer, all styled from its own token set in `style.css`. Every `todo` card anywhere in the tree is a list there — `GET /api/todos` returns them all and writes go back through `PATCH /api/item`, so the same card is edited from both surfaces. Tasks carry extra fields the canvas ignores (`starred`, `due`, `tags`, `note`, `noteStyle`) and blank-text tasks (the canvas editor's placeholder rows) are never listed. Screens are static markup in `index.html` and this module fills the `[id]` regions, so fields holding a caret survive a re-render; while it's open `main.js` hands over the keyboard and pointer via `isQuickNotesOpen()`.
- `capture.js` gets outside content onto the canvas: the `paste` event (images/files upload, URLs become link cards, other text a note), OS drag-and-drop onto `#stage`, and the upload inputs, all through `addFiles` / `addText`. Keyboard copy/cut ride the `copy`/`cut` events (not keydown) and write a `milaclone:item:<id>:copy|cut` marker to the system clipboard, so pasting it deep-copies the card via `/copy` (or `/move` for cut). Pure helpers it relies on (`isUrl`, `embedUrl`, `fileIcon`, `clipMarker`) live in `util.js` and are Vitest-covered.
- Link cards whose URL `embedUrl` recognises (YouTube, Vimeo, Spotify) render an iframe built from the URL alone — the server never fetches it; the iframe ignores the pointer until its card is selected. `lightbox.js` is the full-size image `<dialog>` (double-click an image; ←/→ step in reading order). Image cards carry optional `data.caption` and `data.transparent`; file cards pick a lucide icon by MIME/extension and embed a native `<audio>`/`<video>` for media.
- `trash.js` owns the Trash sheet (`#trashDialog`, a native `<dialog>`), opened from the topbar or the mobile More sheet; restoring or emptying calls `forgetUndo` in `editing.js` so cmd+Z never retries a gone delete. While any `<dialog>` is open, `main.js` ignores global shortcuts.
- `rich.js` owns note/comment bodies: cards show `util.js` `docToDom` (a DOM-built static render — never `innerHTML`; links limited to http(s)/mailto) and `enterEdit`/`exitEdit` mount and destroy the TipTap editor, `import()`ing the bundle the first time any card is edited. `util.js` `isTyping()` is the shared "keyboard belongs to a field" check; it includes a rich body whose editor is still loading.
- `search.js` is the cmd+K `<dialog>` (results open their board, select and centre the card); `export.js` is the topbar Export menu (Markdown of this board, database backup).
- Other modules: `viewport.js` (pan/zoom + `screenToWorld`), `tools.js` (toolbar arming), `editing.js` (select/edit/save), `menus.js` (color palette + context menu), `clipboard.js` (copy/cut/paste), `create.js`, `mobile.js` (mobile header/footer chrome), `api.js` (thin `fetch` wrappers).
- **Colours are tokens.** `:root` in `style.css` defines every surface/ink/border colour and a `prefers-color-scheme: dark` block overrides the same tokens (Quick notes' `--qn-*` set too); there's no in-app theme switch (D8). Use a token, never a literal, for any new background, text or border — white text on a coloured fill is the only literal that stays.
- Lucide icons come from a CDN `<script>` and are refreshed after DOM changes via `refreshIcons()`; the helper no-ops if the CDN failed to load.

**Auto-save model:** every user edit fires a PATCH — there is no explicit save. When the tab becomes visible again, both the canvas (`main.js`) and Quick notes flush their queued saves and then refetch, so edits from another device show up (skipped while a card is being edited). `editing.js` accumulates every field changed in the 400 ms debounce window and flushes pending saves (with `keepalive`) on `pagehide`/hidden. Data keys merge shallowly, so last-write-wins per key — except todo `tasks`: clients send `baseTasks` (the list as last received) and `routes.js` `mergeTasks` does a three-way merge, so the canvas card, Quick notes and other devices don't overwrite each other. There's no realtime sync between clients.

## Data & config

- `data/board.db` (+ `-wal`, `-shm`) — all board content. Delete to reset.
- `public/uploads/` — user-uploaded files (25 MB cap, mime-filtered in `routes.js`; a disallowed type gets 415 and an oversized file 413, each with an `error` the client shows in a toast). The path is hardcoded, not env-configurable — `routes.js` `setUploadHeaders` adds `nosniff` and `Content-Disposition: attachment` (for anything that isn't an inert inline type) to every file resolved under `public/uploads`, so uploaded HTML/SVG can't run on the app's origin. It identifies uploads by directory device+inode (not path strings, so case-insensitive disks and Unicode folding can't dodge it), and `server.js` passes it to the generic `express.static` too, because encoded URLs like `/%75ploads/…` miss the `/uploads` mount.
- Env vars: `PORT` (4321), `HOST` (0.0.0.0), `DATA_DIR` (`./data`).
- Docker: `Dockerfile` is a two-stage alpine build (stage 1 installs build deps so `better-sqlite3` compiles against musl; stage 2 copies `node_modules` in, then the backend files **by name** — add any new top-level module to its `COPY` line). `docker-compose.yml` mirrors the sibling `reflections` deployment on `xbox` — loopback-only port, resource caps, named volumes `milaclone_data` (`/data`) and `milaclone_uploads` (`/app/public/uploads`), fronted by Tailscale Serve.

# Agent add-on notes (`addons/agent/`)

Loaded when you work under `addons/agent/`. The plan is `docs/agent-addon.md` (W3, decisions A2–A21); what users see and what leaves the house is in `README.md`. 1,500-word cap (`npm run check:docs`).

- Its own npm package (ES modules; `@anthropic-ai/sdk` and `@modelcontextprotocol/sdk` pinned exactly). It reaches the board **only through the MCP add-on** (`src/mcp.js`, A9), one MCP client per agent card so the MCP's write log carries `X-Agent-Id` (A21). Never import core files or `addons/mcp/` code.
- **Per-agent scope is enforced here** (`src/tools.js` `fence`): the MCP only knows whether a board is open to agents at all. An agent's scope is its own board plus, with scope "boards", listed boards whose `agentAccess` flag is on; a board opened only by another agent's card is that agent's alone (A3). Every tool argument naming a board, or a card (looked up with `get_item`), must be in scope; changing, moving or trashing a board card (or moving or trashing a column holding one) needs every board under it in scope; agents never change, move or trash a comment an agent wrote, never move a comment to another board, and never send `replyTo`, `agent` or `agentMemory` (stripped); `search` results are filtered; `export_board_markdown` isn't offered (it walks child boards). A title in `scopeBoards` that two flagged boards share names neither (the card stores titles, not ids).
- `writes` (A7): `chat` gets read tools only, `propose` also gets `create_item`/`create_items` redirected into a "Proposed by <name>" column on its own board, `direct` gets every write tool. Comment replies are written by the service, so every agent can answer.
- Comments (A13, `src/comments.js`): a comment starting `@agent` (the board's oldest agent) or `@<name>` is answered once by a comment card with `data.replyTo` and `data.agent`; only an agent's reply counts, and it is posted as a placeholder before the run, so a comment is never run twice, even across a crash, with no local state. **Run one service instance**: two would both answer. Comments an agent writes are stamped with `data.agent` (`tools.js`) and never ask an agent, so agents can't loop or run each other (A16). A failed run answers with the error rather than retrying every poll. Board content is untrusted data, and the system prompt says so.
- **Orchestrator** (`src/orchestrator.js`, W4.1): an agent card on Home. Its scope is Home plus every board with `agentAccess` on (never a board opened only by its own agent), whatever its card says; it also gets `list_boards` (every title), `list_agents` and `delegate`. `delegate` (not for a chat-only orchestrator) writes a comment on the target agent's board signed `agent` and `delegatedBy` with the orchestrator's id, with `delegateTo` (the target's id) and `kind`; `pending` answers an agent-written comment only when both signatures are an orchestrator's and `kind` is `normal`, routed by `delegateTo`, and `tools.js` strips `delegatedBy`/`delegateTo` from model writes, so this is the only way one agent runs another. Only agents on boards in the orchestrator's scope can be named (errors don't reveal others); at most `DELEGATE_CAP` (5) per run. `priority` answers at once (`Service.answer`) and returns the reply; if that throws, the request stays unanswered (the poll never answers a priority one). `normal` waits for the next poll.
- Providers (`src/providers.js`): `anthropic` runs the SDK's Tool Runner (`client.beta.messages.toolRunner` + `betaTool`, effort from the card, refusal fallback on models that take it); `fake` for tests. Other providers answer "not supported yet".
- The page (`src/page.js`, `public/`, W3.3): `node:http`, no framework, at `/agent/` (Tailscale Serve keeps the prefix). No auth, like the board (A10); POSTs must be JSON so a plain cross-site form can't post. It frames the board from `/`, so it must share the board's origin: the board posts its selection only to a same-origin parent (`public/js/embed.js`). Requests run one at a time; receipts live in memory.
- Memory (`src/memory.js`, A8): threads in `agent.db` via `node:sqlite` (Node ≥ 22.13; the Dockerfile silences its experimental warning); `persistent` adds one note with `data.agentMemory = <agent card id>`, shown in each run's context and rewritten by the `remember` tool, even for a chat-only agent.
- Logs go to stderr as JSON lines (`agent.run` with tokens per run).
- Tests start the board (`server.js`) and the MCP add-on as processes (`test/stack.js`): run `npm ci` at the root and in `addons/mcp` first. `npm run test:e2e` runs the page in Playwright from the root's install; it serves the page from the board's origin with `page.route`. The `Agent add-on` workflow is not a required check.
